# TWBot

Русскоязычный Twitch-бот для одного канала: автомодерация, команды, очки, переводы, дуэли, голосование и локальный API. Переработанная версия Cluelesstech98/twitch_bot; происхождение указано в [NOTICE](NOTICE).

## Запуск на Windows

1. Установите **Node.js 24 LTS** с https://nodejs.org/.
2. Скачайте ZIP этого репозитория и распакуйте.
3. Запустите `run.bat`. При первом запуске откроется `config/.env` — заполните его и запустите файл снова.
4. На своём Twitch-канале выдайте отдельному аккаунту бота модератора: `/mod имя_бота`.

`run.bat` устанавливает зависимости из lock-файла, но не скачивает и не запускает сторонние установщики. База создаётся автоматически в `data/`. Компилятор C++ не нужен: используется встроенный SQLite Node.js.

На Linux:

```sh
npm ci --omit=dev
cp config/.env.example config/.env
# заполните config/.env
npm start
```

Запускайте из корня проекта. Для постоянной работы используйте один экземпляр процесса, например systemd или PM2 в fork mode с instances=1. Перед обновлением остановите процесс и сделайте резервную копию всей папки `data/`.

## Доступ к Twitch

Зарегистрируйте приложение в https://dev.twitch.tv/console/apps и получите **пользовательский OAuth-токен отдельного аккаунта бота**, связанный с вашим Client ID. Не используйте токен владельца канала.

В `config/.env` укажите:

- `ACCESS_TOKEN` — токен, с префиксом `oauth:` или без него;
- `CLIENT_ID` — идентификатор приложения;
- `BOT_USERNAME` — логин аккаунта бота;
- `CHANNEL_NAME` — логин вашего канала.

Необходимые scopes: `chat:read`, `chat:edit`, `moderator:manage:banned_users`, `moderator:manage:chat_messages`. Для `!followage` дополнительно нужен `moderator:read:followers`. Бот проверяет токен, его владельца, Client ID и обязательные права при старте и каждый час. Если проверка не проходит, процесс останавливается. Автоматического продления токенов нет: получите новый токен и перезапустите процесс.

Документация Twitch: [OAuth](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/), [проверка токенов](https://dev.twitch.tv/docs/authentication/validate-tokens/).

## Настройка модерации

Бот проверяет ссылки у обычных зрителей, капс и повтор сообщений. **По умолчанию включён режим наблюдения: автоматические действия только записываются в журнал.** В режиме `active` бот применяет удаления и таймауты. Команды с `!` также проходят фильтры. Стример, модераторы и VIP освобождены от автомодерации.

Список запрещённых слов задаётся в `config/moderation.json` и **по умолчанию пустой**. Исходный список содержал нейтральные слова и ошибочно назывался официальным списком Twitch. Автоматического перманентного бана за слова нет. Пример настройки:

```json
{
  "forbiddenWords": ["пример_запрещённого_слова"],
  "wordTimeoutMap": {"пример_запрещённого_слова": 600}
}
```

После изменения перезапустите бота. Фильтр учитывает регистр, Unicode и невидимые разделители, сопоставляет целые слова/фразы. Он не гарантирует обнаружение всех вариантов маскировки. Капс: два предупреждения, затем таймаут. Повторы: предупреждение на втором сообщении, таймаут на третьем в течение 10 секунд.

### Режим наблюдения

В `config/.env`:

```dotenv
AUTOMOD_MODE=observe
```

После изменения перезапустите бота. В режиме `observe` правила работают как обычно, включая счётчики предупреждений за капс и повторы, но бот не вызывает API наказаний/удаления и не публикует автоматические предупреждения в чат. Сработавшие фильтры не передают сообщение дальше в обработчики команд. Ручные команды модераторов и запросы локального API продолжают выполняться.

Решения сохраняются в SQLite: время, канал, логин, ID и текст сообщения, правило (`link`, `forbidden_word`, `caps`, `spam`), план действий, длительность таймаута и режим. В консоли появляется краткая запись с ID события. Чтобы проверить ложные срабатывания, откройте журнал из папки проекта:

```sh
npm run moderation:log
npm run moderation:log -- --limit 50 --mode observe
npm run moderation:log -- --user имя_зрителя
```

Команда выводит JSON с последними событиями; лимит — от 1 до 100. Сравните `message` с `rule` и `actions`, затем скорректируйте `config/moderation.json`. Текст сообщений хранится локально в базе: доступ к папке `data/` должен быть только у владельца установки. При записи журнала удаляются записи старше 30 дней и сохраняется не более 10 000 последних событий.

Когда результаты вас устроят, замените настройку на `AUTOMOD_MODE=active` и перезапустите. В журнале режима `active` фиксируются статусы `pending`, `applied` и `failed`; при сбое записи решения автоматическое наказание не выполняется. В наблюдении статус всегда `observed`. Повторный запуск не применяет прошлые решения из журнала. Смена режима не сбрасывает сохранённые кулдауны; счётчики капса и повторов после перезапуска начинаются заново.

## Команды

| Доступ | Команды |
| --- | --- |
| Все | `!команды`, `!пинг`, `!правила`, `!игра`, `!followage`, `!чебыло`, `!тг` |
| Все | `!iq`, `!подарок`, `!пословица слово`, `!анекдот`, `!судьба` |
| Все | `!очки`, `!перевод @ник 100`, `!топ очки`, `!рулетка` |
| Все | `!дуэль @ник 100`, `!принять`, `!отклонить` |
| Все | `!предложение название игры`, `!голос название игры`, `!итоги`, `!репорт @ник причина` |
| Модератор/владелец | `!варн @ник`, `!таймаут @ник секунды`, `!бан @ник причина`, `!разбан @ник`, `!жалобы`, `!+очки @ник 100`, `!+подарок текст` |
| Владелец | `!0подарки`, `!тест текст` |

Три предупреждения за последние 24 часа приводят к таймауту на 10 минут. Предупреждения хранятся в SQLite. Команды ограничены одним вызовом в 3 секунды на пользователя; рулетка — раз в 5 минут. За активность начисляется не более одного очка за 5 минут. Переводы и дуэли атомарны: выигрыш дуэли переводит ставку от проигравшего, общая сумма очков сохраняется. Ставки не резервируются; при принятии баланс обоих участников проверяется снова.

`TELEGRAM_LINK` и `CHAT_RULES` задают ссылку и правила вашего канала. Подарки текстовые и никогда не наказывают зрителя. Автоматических рекламных сообщений нет.

## Локальный API

По умолчанию выключен. Для включения задайте `API_ENABLED=true`, `API_PORT=3001` и случайный `API_KEY` не короче 32 байт:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Сервер слушает **только 127.0.0.1**. Каждый запрос требует заголовок `x-api-key`. Ключ даёт полный доступ к модерации и очкам. Для удалённого доступа используйте SSH-туннель; не публикуйте порт через прокси без отдельной защиты и TLS.

- `GET /stats/top?type=points&limit=10` — типы `points`, `iq`, `warns`, лимит до 100.
- `GET /stats/user/логин`.
- `POST /command/ban`, `/command/unban`, `/command/timeout`, `/command/warn` — JSON с `username`, при необходимости `duration`, `reason`.
- `POST /points/add` — JSON с `username`, `amount`.

Тело запроса ограничено 8 КБ, запросы — 60 в минуту на адрес. Ошибки не раскрывают внутренние исключения и токены.

## Журнал действий модерации

Ручные команды `!варн`, `!таймаут`, `!бан`, `!разбан`, соответствующие запросы API и действия активной автомодерации записываются в отдельную таблицу SQLite `moderation_actions`. Журнал наблюдения остаётся отдельным: предполагаемое наказание не выдаётся за выполненное.

Сохраняются время, источник (`chat`, `api`, `automod`, `system`), инициатор, Twitch ID модератора и ID команды из чата, канал, команда, действие, получатель, причина, длительность таймаута, HTTP-статус и подтверждение Twitch. Для чата инициатор берётся из Twitch tags. Для API записывается `api_key`: единый ключ не позволяет определить человека, а переданное в JSON поле `actor` не считается удостоверением личности. Автомодерация помечается как `system`; `decision_id` связывает действие с решением фильтра.

Просмотр из папки проекта:

```sh
npm run actions:log
npm run actions:log -- --user ник_зрителя --limit 50
npm run actions:log -- --actor ник_модератора --source chat
npm run actions:log -- --status unknown
```

Команда выводит JSON; `--limit` принимает значения от 1 до 100. Для ручных команд можно указывать причину: `!таймаут @ник 60 повтор сообщений`, `!варн @ник грубость`, `!разбан @ник ошибочный бан`.

| `status` | Значение |
| --- | --- |
| `pending` | Запись создана, итог ещё не сохранён; после сбоя результат требует проверки |
| `confirmed` | Twitch вернул успешный HTTP-ответ на запрос действия |
| `rejected` | Twitch отклонил запрос, например HTTP 403 или 429 |
| `unknown` | Подтверждения нет: сетевой обрыв, таймаут, HTTP 5xx/408; действие могло выполниться |
| `local` | Выполнена локальная логика предупреждения; подтверждение Twitch не запрашивалось |
| `failed` | Действие не отправлено или произошла ошибка до подтверждения |
| `local_error` | Twitch подтвердил действие или локальная логика выполнилась, но дальнейшая локальная обработка завершилась ошибкой |

`confirmation` отдельно показывает `confirmed`, `rejected`, `unknown`, `not_sent` или `not_applicable`. `confirmed` означает успешный ответ API, а не отдельную проверку через EventSub. `local` не подтверждает доставку сообщения в чат. Три локальных предупреждения и созданный ими таймаут связаны через `parent_id`.

Запись создаётся **до** запроса к Twitch. Если создать её не удалось, запрос не отправляется. Успешный ответ Twitch сохраняется до обновления локальной таблицы банов, поэтому сбой локальной базы не превращается в ложный отказ Twitch. При `unknown` или `pending` проверьте состояние зрителя перед ручным повтором: бот не повторяет такие запросы автоматически. Если процесс аварийно завершился, незавершённая запись остаётся для разбора.

При записи удаляются события старше 30 дней; хранится до 10 000 последних записей. Токены, заголовки запросов и сырые сетевые исключения в журнал не записываются. Доступ к `data/` предоставляйте только владельцу установки.

## Границы этой версии

- Это бот для одного канала и одного процесса, а не платформа для множества стримеров.
- Telegram-панель, Android-приложение и система званий отсутствовали в коде исходного снимка. Здесь они не заявляются как готовые функции.
- История категорий фиксирует изменения, замеченные запросами `!чебыло`; это не полная история эфира. Идентификатор активного эфира для голосований обновляется раз в минуту.
- Очки, жалобы, голоса и предупреждения сохраняются. Кулдауны команд, рулетки, жалоб, подарков и начисления очков активности сохраняются в SQLite. После перезапуска отсчитывается оставшееся время. Счётчики капса и повторов сбрасываются после перезапуска.
- Старая база автора не переносится. Для старых изменённых схем автоматическая миграция не обещается; новая установка начинает с чистой базы.
- Автотесты не подключаются к Twitch и не подтверждают работу с реальным токеном. После настройки проверьте команды на тестовом канале.

Подробности исправлений: [SECURITY.md](SECURITY.md).

## Структура обработки чата

- `src/bot.js` — точка входа, проверка конфигурации, сигналы процесса.
- `src/runtime/twitch-bot.js` — подключение Twitch, таймеры, API, завершение и сборка компонентов.
- `src/chat/message-handler.js` — порядок обработки: проверка события → права → фильтры → команды.
- `src/chat/permissions.js` — роли и исключения из автомодерации.
- `src/chat/automoderation.js` — проверка фильтров и составление решений.
- `src/chat/moderation-actions.js` — запись решения, режим наблюдения и выполнение автоматических действий.
- `src/services/action-audit.js` — журналирование фактических действий и подтверждений Twitch.
- `src/chat/sender.js` — очистка, ограничение длины и частоты исходящих сообщений.
- `src/commands/dispatcher.js` — алиасы, явные права команд, кулдауны и вызов обработчиков.
- `src/commands/user-handlers.js`, `moderator-handlers.js` — обработчики команд с явными зависимостями.

`src/services/cooldowns.js` и таблица `cooldowns` в SQLite хранят сроки ограничений отдельно для каждого канала и пользователя. Перезапуск не продлевает срок и не обнуляет его. `!0подарки` владельца очищает сохранённые ограничения подарков.

При добавлении пользовательской команды зарегистрируйте её алиас, обработчик и роль в `USER_ROLES` диспетчера. Без явной роли новый обработчик не выполняется. Команды из таблицы модерации требуют как минимум роль модератора. Фабрики компонентов принимают зависимости, поэтому их можно проверять без подключения к Twitch.
